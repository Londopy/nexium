Q: `fn main() -> !u8`: what is the exit code when `main` returns an error?
- 0
* 1, and the error's name is printed
- 2
> A `u8` result chooses the code; an error from `!` is reported by name with code 1.

Q: Why does `run` return an `i32` status *and* have `!` on its result?
* the status is the decision it made (usage mistake, no such item), the error is what it could not decide (the file failed to load)
- an `i32` cannot hold an error
- `!` is required on every function that reads a file
> Expected outcomes are values; failures are errors. The split keeps `main` short.
