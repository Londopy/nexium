# Nexium の仕組み

コンパイラを理解したい人、変更したい人のためのガイドツアーです。言語リファレンスは
[`language.md`](language.md)、他の言語から Nexium を呼ぶ方法は
[`embedding.md`](../../embedding.md)（英語）、仕様が未定だった箇所で下した
すべての判断は [`DECISIONS.md`](../../../DECISIONS.md)（英語）にあります。

## 一段落で言うと

`nx` は依存のない Rust プログラムです。`.nx` ソースを読み、検査し、一つの C
ファイルを書き出します。その C ファイルは `runtime/nx_rt.h`（コンパイラの
バイナリに埋め込まれた 900 行の素朴な C）をインクルードし、クロスコンパイル用の
libc を同梱した Clang である `zig cc` に渡されます。ガベージコレクタも仮想
マシンも、インストールすべきランタイムライブラリもありません。出力はネイティブの
実行ファイル、共有ライブラリ、静的アーカイブで、ターゲットの C ライブラリにしか
依存しません。

```
 hello.nx ──lex──▶ tokens ──parse──▶ AST ──check──▶ 型付き IR ──cgen──▶ hello.c ──zig cc──▶ hello.exe
                                            │
                                            └──comptime──▶ 定数値、comptime テスト
```

## パイプライン、段階ごとに

### 1. 字句解析器（`src/lexer.rs`）

バイトを受け取り、トークンを返します。ここでの二つの決定が下流のすべてを
形作ります。

- **改行はトークンです。** 文は改行で終わるので、字句解析器は `Newline` を出し、
  連続する改行をまとめます。`(` と `[` の内側では改行が抑制され、これが引数
  リストを複数行に書ける理由です。`{ }` の内側では保持されます。ブロック内の文は
  改行で区切られるからです。
- **`<<` と `>>` は `LtLt` と `GtGt` であり、決してシフト演算子ではありません。**
  バイナリパターンを開くのかビットをシフトするのかは、構文解析器が文脈で判断
  します。

識別子、キーワード、組み込みの名前はすべて `Ident` です。キーワードは構文解析器が
認識します。文字列とコメントの外にある非 ASCII はエラーです。

`nx tokens file.nx` はトークン列を固定形式で出力します。これが `self/lexer.nx` の
セルフホスト字句解析器を検証する基準です。

### 2. 構文解析器（`src/parser.rs`、`src/ast.rs`）

再帰下降で、文法規則ごとに一つの関数があり、関数、struct、enum、trait、impl、
定数、グローバル、import、テスト、アーティファクトからなる `ast::Module` を
作ります。条件は括弧で囲み（`if (c)`）、構造体リテラルは `Point{ .x = 1 }`、
無名のものは `.{ .x = 1 }`、クロージャのキャプチャは明示的に
`|[x, &mut y] a: i32|` と書きます。

行継続の規則は構文解析器にあります。`|>`、`.method(`、`catch`、`orelse`、
`and`、`or` で始まる行は前の行に続き、二項演算子や開き括弧で終わる行も同様です。

### 3. 検査器（`src/check/`）

コンパイラ最大の部分で、約 7,500 行です。AST を `src/tir.rs` の型付き IR に変換
し、すべての診断を生成します。構成要素は次のとおりです。

**型はインターンされます**（`src/types.rs`）。`TyId` は `TyKind` のテーブルへの
インデックスで、二つの型が等しいのは id が等しいときだけです。推論変数も
`TyKind` なので、`let x = 0` は `x` に整数変数を与え、それを確定する最初の使用で
解決されるか、既定で `i64` になります。

**ジェネリクスは単相化されます。** `fn max(comptime T: type, a: T, b: T)` は
呼び出された異なる `T` ごとに一度検査され、組み合わせごとに一つの `TFunc`
インスタンスができます（`check/mod.rs` の `instantiate`）。型パラメータに
実行時の表現はありません。トレイト制約（`where T: Ord`）はインスタンス化時に
検査され、`impl` ブロックは構造的に照合されます。

**所有権は関数ごとのフロー解析です。** `List`、`String`、`Map` の値は所有され
ます。値で代入したり渡したりするとムーブされ、検査器は元のローカルをムーブ済み
としてマークします（`TFunc::moved`）。再び使うと `use after move` エラーです。
フィールドや要素からのムーブは、コンテナが半分だけ所有された状態になるため
拒否されます。引数は借用なので、呼ばれた側はムーブできません。`ref class` の
値は参照カウント付きのポインタで自由にコピーでき、検査器は `refcounts` が必要な
ことだけを記録します。

**エフェクトは不動点で推論されます**（`check/effects.rs`）。本体の検査中、
検査器は関数が直接行うエフェクト `own_effects` を、それぞれ*証人*（位置と
説明の一文、例えば "appending to a List may grow it"）付きで記録します。
すべての呼び出し先も記録します。その後

```
effects(f) = own(f) ∪ ⋃ effects(callee)      不動点まで反復
```

を全インスタンスに対して行います。extern 関数は何でもすると仮定されます。
署名や関数型の `!allocates` のような負の制約は伝播後に検査され、診断は呼び出し
グラフをたどってエフェクトを持ち込んだ関数まで行き、その証人を表示するので、
エラーは呼び出し連鎖の一番下の正確な行を名指しします。`panics` は、操作が
失敗し得ないと検査器が証明できる場所で免除されます：同じスライス上の `for`
のループインデックスによる添字、コンパイル時に既知の添字、オペランドの範囲が
収まる算術です。

束は `src/effects.rs` の 8 ビットです：`allocates`、`refcounts`、`blocks`、
`shared_mutable`、`nondeterministic`、`panics`、`ffi`、`unbounded_stack`
（予約）。

**パターン**（`check/pattern.rs`）は `match` を決定木にコンパイルし、enum と
bool の網羅性を検査します。**バイナリパターン**（`check/binpat.rs`）は
`<<len:16/little, payload:len*8, rest:bytes>>` を、サイズが前の束縛に依存し得る
検査付きビット読み取りの列に変えます。

**リージョン**は保守的に検査されます。関数のローカルへのスライスやポインタを
返すのはエラーです（規則 R1）。

**トレイトオブジェクト**は (trait, 型) の組ごとに vtable を得ます。レシーバを
適応させるサンクとして生成され、`dyn Shape !allocates` は別の型で、そこへ
変換されるすべての実装が制約を満たさなければなりません。

**`@cImport`**（`src/cimport.rs`）はヘッダに `zig cc -E` を実行し、出てきた宣言を
小さな C 宣言パーサで読み、合成モジュールを注入します。生成される C はヘッダ
自身の型名を使うので、ヘッダがレイアウトの唯一の情報源であり続けます。

### 4. コンパイル時評価（`src/comptime.rs`）

型付き IR 上のインタプリタです。`comptime expr`、`const` の初期化子、
`@embedFile`、`comptime test` ブロックは検査中にここで実行されます。純粋な計算、
コレクション、Nexium 関数の呼び出しは許され、I/O、時計、乱数、外部呼び出し、
グローバルは禁止され、ステップ予算があるので暴走した評価はハングではなく
コンパイルエラーになります。失敗した `comptime test` は他のエラーと同様に
`expect` の行で報告されます。

### 5. C バックエンド（`src/cgen/`）

型付き IR は一つの C 翻訳単位に落とされます。`nx emit-c` の出力で見えるものの
大半は、いくつかの約束事で説明できます。

- **すべての関数は隠れた `nx_ctx* c` を受け取ります。** コンテキストは
  アロケータ、現在のアリーナ、stdout/stderr、乱数の状態、argv、リーク追跡の
  カウンタを運びます。ランタイムにグローバルはなく、それが出荷したライブラリを
  ホストプロセスに安全に読み込める理由です。
- **所有された値はスコープ終了時にドロップされます。** バックエンドはスコープの
  スタックを持ち、所有型の各 `Let` がドロップを登録し、スコープを抜けるとき
  （通常、`return`、`break`、エラー）に `defer` と共に逆順でドロップを出力
  します。呼び出しに渡された一時値も登録されます。
- **検査付き算術は呼び出しです。** `x * 7` は
  `nx_mul_i64(x, 7, "hello.nx:3")` になり、位置文字列がパニック時に表示される
  ものです。回り込み（`*%`）と飽和（`*|`）の形は素の C かクランプするヘルパに
  対応します。
- **パニックは `longjmp` です。** スレッドローカルの `nx_boundary` が `jmp_buf`
  を持ち、`nx_panic` はメッセージと位置を埋めて、エントリポイントかエクスポート
  ラッパーが設置した最寄りの境界へジャンプします。
- **`for parallel`**（`cgen/parallel.rs`）は本体をワーカー関数に取り出し、
  外側のローカルにはポインタの構造体を通して到達させ、ランタイムがインデックス
  範囲をハードウェアスレッドに分割します。ワーカーのパニックは捕捉され、
  全ワーカー終了後に呼び出し側で再送出されます。
- **`using arena`** はブロックの間、コンテキストのコピーにバンプアロケータを
  差し込みます。コンテナは作られたアリーナを覚えているので、ブロック内で成長する
  外側の `List` はヒープに住み続けます。

これは降下後の `examples/hello.nx` です：

```c
static void nx_main(nx_ctx* c) {
  nx_sink _t1 = nx_sink_file(c, c->out);
  nx_w(&_t1, (const uint8_t*)nx_str_0, 13);
  nx_w(&_t1, (const uint8_t*)"\n", 1);
  nx_sink_flush(&_t1);
  int64_t x_0 = nx_mul_i64(((int64_t)6LL), ((int64_t)7LL), "examples/hello.nx:3");
  ...
}
```

書式化は解釈ではなくコンパイルされます。`println("x = {}", .{x})` は、引数の型が
わかった上で、プレースホルダごとにシンクへ直接書き込む処理になります。

### 6. ランタイム（`runtime/nx_rt.h`）

一つのヘッダで、`include_str!` によってコンパイラに埋め込まれ、生成される各
ファイルの先頭に貼り付けられます。節は、スライス、アロケータインターフェース、
パニック、任意のリーク追跡付き既定（malloc）アロケータ、アリーナ、parallel-for
のスレッドプール、リスト、文字列、書式化、ハッシュマップ、参照カウント、
バイナリパターンのヘルパ、検査付き算術、そして Windows と POSIX 向けの
プラットフォーム部分（ファイル I/O、時間、プロセス起動）です。

参照カウントは各 `ref class` オブジェクトの前に置かれた 2 ワードのヘッダ
（`rc`、`weak`）です。`nx_retain` はランタイムのインラインなインクリメントで、
解放はバックエンドがクラスごとに生成します（`cgen/mod.rs` の `drop_fn`）。
カウントがゼロになったときにオブジェクト自身のフィールドをドロップする必要が
あるからです。`weak` 参照は割り当ては生かしますがオブジェクトは生かさず、`rc`
がゼロになると `upgrade()` は失敗します。

すべて `static inline` なので、C コンパイラはプログラム全体を一度に見て、
使われないランタイム関数のコストはゼロです。

### 7. ドライバと C コンパイラ（`src/main.rs`）

`nx build` は C ファイルを `nx-out/` に書き、ビルドモード（`debug`、`safe`、
`fast`、`small`）、ターゲットトリプル、`artifact link` の入力に応じたフラグで
`zig cc` を起動し、`--keep-c` がなければ C を削除します。同じ経路が `run`、
`test`（生成されたテストランナーがエントリポイント）、`leaks`
（`-DNX_LEAK_CHECK` を追加）、`size`（`-ffunction-sections` を追加してオブジェクト
を読み戻す）にも使われます。

`zig cc` が既定なのは、そのままクロスコンパイルできるからです。Windows 機から
`--target aarch64-linux-gnu` がそのまま動きます。クロスコンパイルが不要なら
`--cc clang` や `--cc gcc` も受け付けます。

### 8. 出荷（`src/ship.rs`、`src/cgen/exports.rs`）

`nx ship` は `artifact` 宣言を読み、次を生成します。

- **`cabi`**：共有ライブラリ、静的アーカイブ、C ヘッダ。
- **`python`**：ctypes ベースのパッケージと wheel。
- **`rustlib`**：アーカイブをリンクするビルドスクリプト、`extern "C"` 宣言、
  `#[repr(C)]` 構造体、安全なラッパーを持つ Cargo crate。
- **`cli`**：実行ファイル。

エクスポート境界はエフェクトが報われる場所です。`!panics` と証明され、エラー
共用体を返さないエクスポート関数は自然な C 署名を得ます。それ以外のエクスポート
は `int32_t` のステータスを返し、値を出力引数で渡します。ラッパーはパニック
境界を設置するので、ライブラリ内の Nexium パニックはホストでアボートではなく
エラーコードになります。埋め込み可能なアーティファクトを宣言するプログラムでは
可変グローバルが拒否されるので、同じライブラリを読み込む二つのホストが干渉する
ことはありません。

## ツール

すべて同じ型付き IR の上のビューなので、コンパイラと食い違いません。

| ツール | 読むもの |
| --- | --- |
| `nx effects` | 伝播後の `TFunc::effects` |
| `nx refcounts` | すべての `Retain`/`Release`/`Weak`/`Upgrade` ノードとその関数 |
| `nx audit` | `unsafe` ブロックとグローバル |
| `nx doc` | ドキュメントコメント、署名、エフェクトを HTML に描画 |
| `nx lsp` | 編集ごとの完全な検査による診断、`TFunc` からのホバー |
| `nx size` | オブジェクトファイルのセクションサイズを宣言に対応付け |
| `nx fmt` | トークン列だけ。行を結合も分割もしない |

## セルフホスティング

コンパイラは `self/` の下で Nexium に書き直されつつあり、一段階ずつ、各段階は
同じ入力に対する Rust コンパイラの出力との差分で検証されます。字句解析器は完成
し、`cargo test` の一部です。次は構文解析器で、その AST は id アリーナ、すなわち
`List` に入ったノードがインデックスで互いを参照する形になります
（`examples/tree.nx` 参照）。再帰型は不要で、一度に解放できます。四つの段階が
揃ったら、Rust の `nx` が Nexium の `nx` を一度コンパイルし、そのバイナリが自分の
ソースをもう一度コンパイルし、二つの出力がバイト単位で一致すれば、言語は自分自身を
ビルドしたことになります。

## 何かがおかしいときに見る場所

| 症状 | ここから |
| --- | --- |
| 構文解析が通るべきでないのに通る、またはその逆 | `src/parser.rs`、次に期待メッセージのある `tests/compile_fail/` |
| おかしく見える型エラー | `src/check/expr.rs`（式）または `src/check/method.rs`（メソッドと組み込みの呼び出し） |
| あるべき、またはあるべきでないエフェクト | `own_effects` の証人。`src/check/` で `add_effect` を検索 |
| `nx leaks` でのリーク | `src/cgen/expr.rs` のスコープスタック。所有された一時値はすべて登録が必要 |
| 生成された C がコンパイルできない | `nx emit-c file.nx --keep-c` で `nx-out/file.c` を読む。呼んでいるランタイムヘルパは `runtime/nx_rt.h` |
| `for parallel` や `using arena` 内のクラッシュ | `src/cgen/parallel.rs` とランタイムのアリーナの節 |
